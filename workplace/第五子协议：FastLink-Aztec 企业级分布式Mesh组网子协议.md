## 二、技术背景与行业痛点

1. 传统 IPsec/SSL VPN：需要公网服务器，部署复杂、成本高、单点故障风险大，跨运营商延迟 \&gt; 200ms

2. ZeroTier/Tailscale：强依赖官方根服务器，国内访问延迟高、数据存在泄露风险，无法完全私有化部署

3. 传统 SD\-WAN：价格昂贵、部署周期长、维护成本高，中小企业无法承担

4. 跨地域组网：国内三大运营商互通差，跨地域办公延迟高、丢包严重

5. 合规问题：企业数据不能出境，不能使用境外服务器，传统方案无法满足等保要求

## 三、核心原理拆分

1. **无中心 Mesh 自组织原理**
所有节点完全对等，没有中心控制节点：

- 节点启动后自动发现其他节点

- 自动建立 P2P 连接，形成 Mesh 网络

- 节点离线自动重新路由，网络自愈

- 支持最多 1000 节点的大规模组网

2. **零服务器节点发现原理**
基于母协议 DHT \+ 本地 mDNS 实现三层节点发现：

- 本地局域网：mDNS 自动发现

- 企业内网：DHT 私有网络发现

- 公网节点：企业私有 DHT 节点发现

- 完全不需要官方服务器，企业可以部署自己的私有 DHT 节点

3. **企业级多跳智能路由原理**
基于母协议五维路由算法，增加企业专属权重：

新增 $\zeta S$：安全优先级权重，优先选择企业自有节点，避免使用第三方中继节点

4. **透明二层组网原理**
基于 TUN/TAP 虚拟网卡实现透明二层组网：

- 所有节点自动分配企业内网 IP

- 支持 Windows 文件共享、远程桌面、打印机共享

- 和本地局域网完全一致，上层应用无需任何修改

- 支持 VLAN 隔离，不同部门网络完全隔离

5. **细粒度访问控制原理**
基于公钥的 RBAC 权限控制：

- 每个节点的身份就是它的公钥

- 支持按用户、按部门、按资源设置访问权限

- 支持黑白名单机制

- 所有访问操作都有审计日志

## 五、技术与核心细节

### 5\.1 Mesh 节点角色

所有节点完全对等，支持三种可选角色：

- **普通节点**：终端设备，如电脑、手机、服务器

- **边缘节点**：部署在企业出口，作为其他节点的中继

- **私有 DHT 节点**：企业自托管的 DHT 节点，用于内部节点发现

- 没有中心节点，任何节点都可以担任任何角色

### 5\.2 IP 地址管理

- 企业网络使用 \[10\.0\.0\.0/8\]\(10\.0\.0\.0/8\) 私有地址段

- 每个节点自动分配唯一的 IP 地址，基于公钥哈希生成

- 支持手动指定 IP 地址

- 自动检测 IP 冲突，冲突时自动重新分配

### 5\.3 路由计算与更新

- 每个节点定期向邻居节点发送路由更新

- 路由更新间隔：10 秒

- 路由超时时间：30 秒

- 最大跳数：3 跳，避免过多中转导致延迟过高

- 优先选择同运营商、同地域、企业自有节点

### 5\.4 访问控制规则

- 支持基于源 IP、目标 IP、端口、协议的访问控制

- 支持基于节点公钥的身份认证

- 支持按部门分组，不同部门之间默认隔离

- 支持临时权限，到期自动失效
