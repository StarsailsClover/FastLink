# 第一子协议：FastLink\-P2P 零服务器穿透子协议

## 一、定位与职责

### 核心定位

**母协议穿透引擎的业务具象化子协议**
唯一职责：**纯无中心、零信令、零服务器** 完成全网 NAT 节点直连建立，不做加密、不做转发、不做业务，只做「打洞建连」。

### 不可突破约束（继承母协议铁律）

1. 禁止强制依赖任何公网服务器 / 信令节点

2. 完全复用母协议：加密、报文头、握手流程、NAT 检测、时间同步

3. 自动适配三大运营商 NAT4 行为参数，不可自定义硬编码

4. P2P 建连失败自动上报母协议调度器，无缝切 Server 兜底

5. 建连成功后连接池交由母协议统一复用，子协议不单独持有连接

## 二、技术背景与行业痛点

1. 市面 WebRTC /libp2p 对称 NAT4 穿透率国内仅 20%–35%

2. 通用打洞算法不匹配**移动 / 电信 / 联通**端口生命周期、端口块分配规律

3. 传统打洞无时间窗口补偿，时钟偏移直接导致碰撞失败

4. 无预映射保活，NAT 空闲回收导致刚打通立刻断连

5. 无角色互换、无指数退避重试，异常场景容错极差

## 三、核心原理拆分（完全基于母协议底座）

1. **共享种子确定性端口生成原理**
双方离线共享 32B 密钥种子，同哈希函数生成**完全一致端口序列**。

2. **生日悖论碰撞概率原理**
端口样本集越大，NAT 端口映射碰撞概率指数趋近 100%。

3. **预映射 \+ 时间窗口重叠原理**
提前抢占 NAT 映射、200ms 滑动窗口抵消全网时钟偏差。

4. **端口块区间探测原理**
不遍历全 65536 端口，只在本机 NAT 实际分配块内生成，大幅提升命中率。

5. **对称 NAT 反向约束原理**
把对方公网端口区间编码进种子，本方只在对方区间内生成端口，解决对称 \+ 对称 NAT 死局。

### P2P 子协议内部模块拆分

1. NAT 策略适配模块：加载三网 NAT 参数模板

2. 端口序列生成模块：HMAC\-SHA256 确定性生成

3. 预映射保活模块：定时空包维持 NAT 映射

4. 多算法并发打洞模块：IPv6 / 本地 mDNS/BirthdayPunch/TCP 同时打开

5. 建连状态机模块：空闲→探测→预映射→打洞→已连通→断开

6. 失败重试 \&amp; 角色互换模块：3 次指数退避、主动 / 被动互换

7. 结果上报调度模块：成功 / 失败质量数据回传母协议调度器

## 五、技术细节核心实现

### 5\.1 端口生成规则（固定规范，不可改动）

```Plain Text
port_n = HMAC-SHA256(seed + seq_n) mod 65536
```

按运营商自动分配生成端口数量：

- 移动：32 个

- 电信：48 个

- 联通：64 个

### 5\.2 时序控制规范

- 预映射提前：固定 10s

- 时间窗口偏移：±200ms 自适应扩大

- 单端口发包间隔：10–50ms 随机抖动（防 DPI 特征）

- 单次打洞总超时：3s

### 5\.3 状态机完整流转

空闲 → NAT 类型探测 → 端口块探测 → 时间同步校准 → 预映射发包 → 并发端口打洞 → 握手校验 → 连通入库 → 后台保活监听 → 断开触发重连 / 切兜底

## 六、报文规范（完全复用母协议通用报文头）

仅复用母协议 28B 标准头，子协议只定义**Payload 业务结构**，不自定义报文头。

- 报文类型 Type：固定 0x01 归属 P2P 子协议

- Payload 包含：节点公钥、随机数、NAT 类型、端口块区间、签名

握手流程**完全复用母协议四步握手**，不新增私有流程。

## 七、边界异常处理

1. 本地端口占用 → 自动跳过、顺延备用端口

2. 时钟偏移超 200ms → 自动扩窗口至 500ms 重试

3. 首次打洞失败 → 互换主被动角色，指数退避重试 3 次

4. NAT 映射超时回收 → 后台静默重新打洞，上层无感知

5. 本地防火墙拦截 UDP → 自动降级尝试 TCP 同时打开

## 八、最坏场景 \&amp; 四级兜底

1. 最坏场景：对称 NAT \+ 对称 NAT、全网 UDP 封禁、时间完全不同步

2. L1 兜底：切换其余 5 种 P2P 备选穿透算法

3. L2 兜底：全部 P2P 失败，通知母协议切 Server 中继

4. L3 兜底：Server 不可用，切 ICMP/DNS 隧道备用

5. L4 兜底：全部路径失效，优雅断连不污染主网络

## 九、安全设计（继承 \+ 补充）
