# 第六子协议：FastLink\-Chat 零服务器端到端加密即时通讯子协议

**最后一个子协议**，严格沿用统一 12 维拆解框架，**100% 复用母协议 \+ P2P\+Server\+Swift\+Games 底层能力**，不重复实现穿透、加密、路由、抗 DPI，仅专注去中心化 IM 专属特性。专为 BoomChat 打造，彻底颠覆传统中心化 IM 架构。

## 一、定位与职责

### 核心定位

FastLink 生态**纯零服务器端到端加密即时通讯子协议**，实现：

1. 无任何官方服务器、无消息服务器、无存储服务器、无认证服务器

2. 所有消息、文件、音视频数据 100% 端到端加密，仅收发双方可解密

3. 所有数据仅存储在用户本地设备，不上传任何第三方

4. 支持文字、图片、文件、语音、视频通话、群聊全功能

### 核心约束（继承母协议铁律 \+ IM 专属）

1. **绝对零服务器**：禁止任何形式的中心化节点参与消息传输、存储、认证

2. 完全复用底层：穿透、加密、报文、握手、调度、抗 DPI 全盘复用前面子协议

3. **数据主权完全归用户**：所有数据加密存储在用户本地，项目方无法获取任何数据

4. 强制端到端加密：所有通信默认加密，不支持明文传输

5. 无日志设计：所有节点默认不记录任何消息、连接、行为日志

## 二、技术背景与行业痛点

1. 传统 IM（微信 / QQ）：完全中心化，所有数据存储在服务器，可被审查、泄露、监控，无隐私可言

2. 半去中心化 IM（Telegram/Signal）：依赖官方服务器，消息经过服务器中转，存在单点故障和数据泄露风险

3. 纯去中心化 IM（Session/Briar）：基于 Tor 网络，延迟高、速度慢、节点少、稳定性差，不适合日常使用

4. 无离线消息支持：传统纯 P2P IM 对方离线时无法发送消息

5. 群聊规模受限：去中心化群聊通常只能支持几十人，无法满足大规模使用需求

## 三、核心原理拆分

1. **纯零服务器身份认证原理**
基于母协议公钥身份体系：

- 用户身份 = Ed25519 公钥，全球唯一

- 用户 ID = SHA\-256 \(公钥\)

- 无需注册、无需手机号、无需邮箱，生成密钥对即可使用

- 身份验证通过公钥签名完成，无需第三方认证机构

2. **P2P 直连消息传输原理**
基于 FastLink\-P2P 穿透能力：

- 两个用户通过二维码 / 助记词交换公钥

- 自动尝试 P2P 直连，失败则自动通过共同好友节点中继

- 所有消息端到端加密，中间节点无法解密

- 消息发送后自动删除本地临时缓存

3. **分布式离线消息中继原理**
解决纯 P2P IM 最大痛点：对方离线时无法发消息

- 当接收方离线时，发送方将加密后的消息临时存储在**3 个在线的共同好友节点**上

- 消息设置 7 天 TTL，到期自动删除

- 接收方上线后，自动从所有共同好友节点拉取离线消息

- 消息拉取成功后，所有中继节点自动删除该消息

- 没有任何中心化离线服务器，所有中继都是用户自愿提供的节点

4. **双棘轮端到端加密原理**
基于 Signal 双棘轮算法，结合母协议加密体系：

- 每次消息都生成新的临时密钥

- 支持前向保密：即使长期密钥泄露，也无法解密之前的消息

- 支持后向保密：即使某次会话密钥泄露，也无法解密之后的消息

- 所有消息都经过签名，防止篡改和伪造

5. **分布式 Mesh 群聊原理**
基于母协议 Mesh 组网能力：

- 群 ID = SHA\-256 \(群主公钥 \+ 群名\)

- 群消息通过 Mesh 网络多跳中继传输

- 每个群成员都可以转发群消息

- 支持最多 100 人的群聊

- 群主可以管理群成员、踢人、解散群

6. **P2P 实时音视频原理**
复用 FastLink\-Games 低延迟传输能力：

- 音视频数据通过 P2P 直连传输

- 使用 Opus 音频编码、H\.264 视频编码

- 自适应码率，根据网络质量自动调整清晰度

- 内置 FEC 前向纠错，丢包率 \&lt; 10% 时无卡顿

## 五、技术与核心细节

### 5\.1 消息格式规范

```Plain Text
Message {
    message_id: [u8; 32], // SHA-256(内容+时间戳+发送者公钥)
    sender: [u8; 32],     // 发送者公钥哈希
    receiver: [u8; 32],   // 接收者公钥哈希
    timestamp: u64,       // 发送时间戳
    type: u8,             // 消息类型：文字/图片/文件/语音/视频
    content: Vec<u8>,     // 加密后的消息内容
    signature: [u8; 64],  // 发送者私钥签名
    ttl: u32,             // 消息TTL，默认7天
}
```

所有消息内容使用 AES\-256\-GCM 加密，密钥由双棘轮算法生成。

### 5\.2 离线消息中继机制

1. 发送方检测到接收方离线后，获取自己和接收方的共同好友列表

2. 选择 3 个在线的、信誉值最高的共同好友节点

3. 将加密后的离线消息发送给这 3 个节点

4. 中继节点验证消息签名后，临时存储该消息

5. 接收方上线后，向所有共同好友节点发送离线消息拉取请求

6. 中继节点将存储的离线消息发送给接收方

7. 接收方收到消息后，发送确认回执给中继节点

8. 中继节点收到确认后，立即删除该消息

9. 消息超过 7 天 TTL 后，所有中继节点自动删除

### 5\.3 双棘轮算法实现

- 根密钥：由双方 ECDH 密钥交换生成

- 发送棘轮：每次发送消息更新

- 接收棘轮：每次接收消息更新

- 每个消息使用独立的消息密钥

- 支持密钥轮换，每隔 1000 条消息自动更换根密钥

### 5\.4 分布式群聊机制

1. 群主创建群，生成群 ID 和群密钥

2. 群主邀请成员加入，将群密钥发送给成员

3. 群成员加入后，自动与其他群成员建立 P2P 连接

4. 群成员发送群消息时，将消息广播给所有相邻的群成员

5. 相邻群成员收到消息后，转发给其他未收到的群成员

6. 所有群消息使用群密钥端到端加密

7. 群主可以更新群密钥，踢出的成员将无法解密后续消息

## 七、边界情况处理

1. 对方离线 → 自动将消息发送给 3 个共同好友节点中继

2. 共同好友都离线 → 消息加密缓存到本地，每隔 10 分钟自动重试发送

3. 消息丢失 → 自动重传，最多重传 3 次，失败则提示用户

4. 群成员离线 → 群消息通过其他在线成员中继

5. 网络分区 → 分区内群聊正常运行，网络恢复后自动同步消息

6. 中继节点恶意篡改消息 → 接收方验证签名，自动丢弃无效消息

## 八、最坏场景与四级兜底

1. 最坏场景：所有共同好友都离线、DHT 被完全封锁、无法发现任何节点

2. L1 兜底：支持通过二维码 / 助记词手动交换节点信息，直连发送消息

3. L2 兜底：自动启用 Server 子协议中继，通过社区自托管节点转发消息

4. L3 兜底：消息加密缓存到本地，无限期等待对方上线

5. L4 兜底：提示用户当前网络环境无法通信，所有数据安全保存在本地

## 九、安全设计

继承母协议 \+ 所有子协议安全体系；
子协议新增 IM 专属安全：

- **强制双棘轮端到端加密**：所有消息、文件、音视频都加密，仅收发双方可解密

- **前向保密 \+ 后向保密**：即使密钥泄露，也无法解密之前和之后的消息

- **元数据保护**：隐藏消息发送者、接收者、时间戳等元数据，防止流量分析

- **防中间人攻击**：支持公钥指纹手动验证，确保通信双方身份

- **无日志设计**：所有节点默认不记录任何日志，无法追溯用户行为

- **阅后即焚**：支持消息阅后即焚，阅读后自动从双方设备删除

- **远程销毁**：支持远程销毁自己发送的所有消息
