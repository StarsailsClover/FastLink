## 二、技术背景与行业痛点

1. 传统 ZeroTier/Tailscale 强依赖官方根节点，国内延迟高、有风控单点故障

## 三、核心原理拆分

1. **DHT 节点自注册原理**
Server 节点启动后将自身信息（IP / 端口 / 运营商 / 负载 / 地理位置）签名写入 DHT 指定 Key 域，全网节点可去中心化检索。

2. **五维加权智能路由原理**
综合 延迟、丢包、跳数、运营商匹配、地理距离 计算权重，**权重越小优先级越高**，自动择优中继节点。

3. **无感知路径迁移原理**
母协议调度层统一托管连接，Server 链路质量下降时，后台预建立新中继，流量平滑迁移，上层无断连。

4. **中继透明转发原理**
Server 仅做**加密报文二层透传**，不解密、不解析业务载荷，保证隐私与安全边界。

5. **四层节点信誉治理原理**
行为评分 \+ 异常检测 \+ 黑名单 \+ 数据签名校验，自动过滤恶意、高延迟、高丢包节点。

## 五、技术与核心细节

### 5\.1 节点信息字段（固定规范）

- NodeID（32B 公钥哈希）

- 公钥（32B）

- 外网 IP \+ 端口

- 运营商标签：移动 / 电信 / 联通 / 国际

- 地理位置编码

- 当前负载连接数

- 带宽上限、丢包率、平均延迟

- 签名域：整段信息 Ed25519 签名防篡改

### 5\.2 五维路由权重公式

- $D$：归一化延迟

- $L$：归一化丢包率

- $H$：跳数

- $O$：运营商跨网惩罚（同网 0，跨网 1）

- $G$：地理距离归一化

- 固定权重：$\alpha=0.4,\beta=0.3,\gamma=0.1,\delta=0.15,\epsilon=0.05$

### 5\.3 中继转发规则

- 仅转发**已加密完整报文**，不拆解、不解密

- 单节点最大并发连接可配置，超限拒绝新接入

- 按来源 IP 做流量隔离，防止互相攻击

- 空闲连接自动超时回收，释放资源

### 5\.4 信誉系统扣分规则

- 握手失败：\-20

- 频繁丢包断连：\-30

- 篡改报文 / 签名无效：\-100 直接拉黑

- 长期高负载拒绝接入：\-15

- 稳定低延迟低丢包：\+5 / 次健康检测

## 七、边界情况处理

1. DHT 检索无可用 Server → 降级提示，启用本地备用静态节点列表

2. 选中中继节点中途离线 → 500ms 内自动切换次优节点

3. 中继负载满载 → 自动跳过，顺延下一个低负载节点

4. 跨网延迟过高 → 路由算法自动加大跨网惩罚，优先同运营商备选

5. 节点签名校验失败 → 直接丢弃并计入恶意节点黑名单

## 八、最坏场景与四级兜底

1. 最坏场景：所有公网 Server 被封禁、DHT 污染严重、无任何中继可用

2. L1：自动切换静态备选节点池

3. L2：启用 ICMP/DNS 隧道极简中继

4. L3：退回仅本地局域网节点通信

5. L4：全网服务不可用时优雅降级，不阻塞上层应用
